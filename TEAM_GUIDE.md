### Специфичное ограничение этого трека
**Encoder-классификаторы (обученные модели intent-классификации) запрещены для выбора сценария.** Поэтому DistilBERT-классификатор из диплома Дарии **не используется** для роутинга. Из диплома взято только то, что не является классификатором: `detect_language()` (ru/kk/mixed) и общий архитектурный паттерн "оценить → решить → объяснить".

## ТЗ трека — ключевые технические требования

- **Вход по полному ТЗ:** голос через микрофон в вебе обязателен, ответ должен озвучиваться; текст — дополнение. Две проверочные реплики на казахском, одна — смешанная RU/KK.
- **Оценивается только качество маршрутизации**, не синтез/распознавание речи
- **Задержка:** в полном ТЗ требуется короткая пауза до голосового ответа. Отдельно измеряем STT/router/reply/TTS/total; текущая буферизованная озвучка не подтверждает секундный бюджет. Ускорение/стриминг остаются отдельной задачей.
- **Диалог:** до 10 реплик, поддержка переключения темы и возврата, смешанная ru/kk речь
- **Trace panel** обязательна: `turn, transcript, language, scenarios, alternatives, reason, slots, actions, latency_ms`

### Reference architecture (из ТЗ)
```
mic → STT → Layer 1: Triage → Layer 2: LLM Router → Decision policy → Scenario executor → Response → TTS
```
- **Triage** (правила, не ML): язык, нормализация чисел/телефонов/дат, срочность (авария/за границей/мошенничество), разбиение multi-intent
- **LLM Router**: вход — реплика + состояние диалога + каталог сценариев; выход — JSON-контракт `{scenarios[{scenario_id, confidence, reason}], alternatives, language, slots, is_continuation}`
- **Decision policy**: `confidence ≥0.75` → выполнить; `0.45–0.75` → уточнить; `<0.45` дважды подряд → передать оператору
- **Executor**: идентификация клиента → сбор слотов → вызов действий → подтверждение необратимых действий → закрытие

### Данные (в `data/case_2/voice_router_dataset/`)
`scenarios.json` (40 сценариев + 3 системных интента), `slots.json`, `actions.json` (31 действие), `knowledge_base.json`, `mock_backend.json` (11 клиентов/полисов), `dialogs_sample.json` (10 эталонных диалогов), `dev_utterances.json` (104 размеченные фразы для самопроверки), `evaluate.py` (готовый скорер).

## Голос RU/KK/mixed — локальное исправление

Ветка `codex/voice-ru-kk-mixed` основана на `main` с объединёнными PR #3 и #5. Сохранён локальный ввод с микрофона. STT: `gpt-4o-transcribe`, двуязычная лексическая подсказка, без фиксированного `language`; `verbose_json` не применяется. TTS: `gpt-4o-mini-tts`, явная инструкция произношения.

Исправлен сброс языка: `router_output.language` учитывается, номера/ИИН не переключают KK на RU, смешанная речь получает ответ на преобладающем языке клиента. Каталожные вопросы слотов произносятся на выбранном языке. Локализация динамических данных отделена от выбора сценария; проверяется сохранность чисел и идентификаторов. Ошибки STT/TTS видны, повтор озвучки не повторяет действие.

Перед показом: проверить три языка своим микрофоном и аудиоплеер браузера. Синтетическая API-проверка не заменяет проверку произношения человеком. Секундная задержка пока не достигнута; существующие `_apply_*_boundary` в роутере и финальная сдача на сайте остаются отдельными пунктами.
