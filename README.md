# Stone — Saqta Insurance Voice Router

## Описание решения и назначение

Демонстрационный текстовый интерфейс голосового агента вымышленной страховой компании Saqta Insurance. LLM выбирает сценарии из 40 бизнес-сценариев и трёх системных намерений, извлекает слоты, а приложение выполняет мок-действия над синтетическим датасетом. Текстовый ввод разрешён условиями кейса как резервный вариант голосового ввода. Данные и цены не относятся к реальной страховой компании.

## Архитектура

`app.py` принимает реплику → `backend.triage` определяет язык и нормализует телефон → `backend.router` через OpenAI API возвращает JSON с выбранными сценариями, уверенностью и слотами → `backend.decision_policy` применяет пороги 0,75/0,45 → `backend.executor` проверяет идентификацию и слоты, показывает предварительный результат и запрашивает подтверждение перед необратимыми действиями → `backend.actions_mock` обращается к синтетическим данным. Справа в Streamlit показана трассировка решения.

Маршрутизация сценариев выполняется LLM. Обученный encoder-классификатор намерений в проекте не используется.

## Используемые технологии

Python 3.11+, Streamlit, OpenAI API, python-dotenv; JSON-файлы из `data/case_2/voice_router_dataset` служат каталогом сценариев, мок-бэкендом и базой знаний. Данные читаются локально, внешняя база данных не нужна.

## Установка

Из корня репозитория:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Запуск

Создайте `.env` в корне репозитория, задайте `OPENAI_API_KEY`, затем:

```bash
python -m streamlit run app.py
```

Откройте локальный адрес, который выведет Streamlit. Для демо нужен доступ к OpenAI API; личный аккаунт эксперта в приложении не требуется. Поле чата принимает текстовые реплики клиента.

## Зависимости

Зависимости перечислены в `requirements.txt`. Датасет уже включён в репозиторий. При запуске роутер отправляет реплику и каталог сценариев в OpenAI API; без доступного ключа маршрутизация не работает.

## Переменные окружения

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `OPENAI_API_KEY` | Да | Ключ OpenAI API для LLM-маршрутизатора |
| `ROUTER_MODEL` | Нет | Модель роутера; по умолчанию `gpt-4o-mini` |

`.env` исключён из Git. Не помещайте ключ в коммиты и скриншоты.

## Порядок проверки основного сценария

1. Запустите приложение и введите: «Сколько стоит ОГПО для легковой машины в Алматы?». Панель трассировки должна показать SC01; бот запросит недостающие слоты.
2. Введите ИИН водителя из `data/case_2/voice_router_dataset/mock_backend.json` и остальные запрошенные данные. Проверьте расчёт стоимости и действия в панели трассировки.
3. Для проверки подтверждения запросите покупку ОГПО (SC02), предоставьте запрошенные номер автомобиля, ИИН и телефон синтетического клиента. До ответа «да» действие `create_policy` должно оставаться в режиме `pending`.
4. Для проверки системного намерения введите запрос о кредите: ожидается `SYS_OUT_OF_SCOPE`.

Датасет и полное описание кейса: `data/case_2/voice_router_dataset/README.ru.md`. Оценка на размеченных репликах:

```bash
python predictions.py
python data/case_2/voice_router_dataset/evaluate.py predictions.json data/case_2/voice_router_dataset/dev_utterances.json
```

Результат текущего коммита следует фиксировать после фактического прогона с настроенным API-ключом; локальный прогон без ключа невозможен.

## Переиспользованные компоненты

`backend.triage.detect_language()` переиспользован из предыдущего проекта команды AI Firewall. Это вспомогательное определение языка, не классификатор намерений и не основная часть решения. Обученная модель DistilBERT для классификации намерений из того проекта здесь не используется.
