Ветка `codex/voice-ru-kk-mixed` основана на актуальном `main` (`d267ee8`). Параллельное оформление интерфейса из `470d979` сохранено.

## Проверено

- 80 offline-тестов: регрессия приложения, языки, параметры STT/TTS, вопросы слотов, сохранение языка после идентификатора, повтор STT/TTS и одновременный текстовый/голосовой ввод.
- Независимое ревью выявило повтор старой записи после текстового ввода. Исправление покрыто регрессионным тестом.
- Реальный Streamlit AppTest: микрофон подменён синтетическим WAV, остальные стадии выполнялись через реальные API: STT → LLM-router → мок-действия → локализация → TTS.

## Ограничения

- На первом синтетическом прогоне STT исказил казахское слово «төлеуге», что привело к SC28 вместо SC31. После расширения общего словаря STT и повторения с другим синтетическим голосом последующие проверки выбрали SC31. Это не доказывает отсутствие ошибок на живой речи: в финальной mixed-транскрипции также была небольшая орфографическая ошибка без потери сценария.
- Синтетические записи и AppTest не проверяют реальный микрофон, разрешения браузера, автозапуск и качество произношения на слух.
- 8–10 секунд до готового аудио превышают секундный бюджет. `tts` — полная генерация MP3, не время до первого чанка.
- Прежние метрики качества роутинга этой задачей не перепроверялись. `_apply_*_boundary` не изменены; соответствие этих правил официальному ТЗ рассматривается отдельно.

## Ручная проверка

1. Запустить `.venv/bin/python -m streamlit run app.py`, открыть страницу и разрешить микрофон.
2. Произнести русский, казахский и смешанный запросы. В трассировке проверить `ru`, `kk`, `mixed`; прослушать ответы.
3. Ответить на казахский запрос номера одними цифрами: язык ответа остаётся `kk`.
4. При ошибке API использовать кнопку повтора распознавания/озвучки; действие не должно выполняться повторно.

## Сверка с архивом заказчика

Все 11 содержательных файлов архива совпали с репозиторием; подробности в `customer-materials.md`.

После добавления преобладающего языка ответа выполнен новый API-прогон всех 104 реплик с официальным `evaluate.py`: основной сценарий 102/104 (98,1%), полный набор 101/104 (97,1%), multi-intent recall 96,2%. Ошибки: U012 (SC39 вместо SC06), U034 (SC30 вместо SC17), U093 (пропущен SC33). Это текущий замер, не гарантия скрытой оценки.

Первичный язык LLM совпал в 101/104 случаях. После исправления распознавания явного смешения языков повторная обработка тех же сохранённых API-ответов дала 104/104 языковых меток, включая все 7 mixed. Это повторная обработка, не ещё один полный API-прогон.

Ответ на mixed теперь выбирается по преобладающему языку, а при неопределённости сохраняется прежний язык ответа. Добавлены проверки на D04/D10 и вопросы слотов по одному.
