# Проверка качества роутера — 23.09.2026

Локальная ветка `codex/router-boundary-fixes`, база `4c15edb` (main после PR #1).
Модель `gpt-4o-mini`, `temperature=0`, реальные запросы к API. Метрики рассчитаны
штатным `data/case_2/voice_router_dataset/evaluate.py`; данные и метки организаторов
не изменялись.

## Изменение

Уточнены границы SC18/SC14 (документы или регистрация ущерба), SC26/SC30
(доставка выпущенного полиса или проблема выпуска после оплаты), SC38
(подозрительное обращение от имени страховщика) и SC39 (страховая справка).
Добавлены контрастные русские и казахские примеры. Каталог и правила передаются
в системном сообщении; реплика и история клиента — отдельно в пользовательском.
Выбор сценария по-прежнему выполняет LLM, без подстановки ответов по текстам dev.

`predictions.py --input` позволяет прогонять отдельный набор, сохраняя dev по умолчанию.
`tests/router_boundaries.json` содержит 24 дополнительных примера, включая противоположные
ситуации, посторонние услуги и три запроса с несколькими намерениями.

В базовом прогоне ошибки: U035, U051, U075, U076. В финальном прогоне dev ошибок нет,
включая U077 (справка для визы), который ошибался в более раннем пользовательском прогоне.
Сохранились оба ранее ошибочных дополнительных случая:

- **B13:** «Визаға тапсыру үшін ағылшын тілінде анықтама бере аласыздар ма?» —
  ожидание SC39, получено SYS_OUT_OF_SCOPE.
- **B16:** «Нужна медицинская справка о состоянии здоровья для визы.» —
  ожидание SYS_OUT_OF_SCOPE, получено SC39.

Пять существующих unit-тестов, компиляция и `git diff --check` проходят.
Четыре отдельные живые проверки ответа на вопрос о слоте сохраняют активный сценарий
и `is_continuation=true`: SC21 (специальность врача), SC39 (вид документа),
SC26 (канал доставки), SC18 (вид страхования). Полный интерфейс и executor этой
правкой не проверялись.

## Ограничения измерения

Это по одному финальному прогону каждого набора, а не гарантия стабильных 100%.
Dev и дополнительные примеры использовались при настройке промпта, поэтому результаты
не являются оценкой на скрытой тестовой выборке. Ответы модели могут меняться даже
при `temperature=0`; оставшиеся ошибки сохраняем явно и не меняем под них разметку.

На dev при четырёх параллельных запросах медиана времени одного вызова `route()`:
1,353 с до изменения и 1,606 с после; p95 — 2,287 и 2,276 с соответственно.
Замер включает сеть и API, условия не изолированы. Бонусная цель 500 мс пока
не достигнута. Продолжать бесконечную настройку на dev не следует: следующая
проверка качества нужна на новых формулировках и в полном диалоге.

## Как воспроизвести

Из корня репозитория, после установки `requirements.txt` и настройки
`OPENAI_API_KEY` в локальном `.env` (или окружении). Для сравнения использовать
`ROUTER_MODEL=gpt-4o-mini`. Живые прогоны расходуют API-квоту.

```bash
python -m unittest discover -s tests -v
python predictions.py
python data/case_2/voice_router_dataset/evaluate.py predictions.json data/case_2/voice_router_dataset/dev_utterances.json
python predictions.py --input tests/router_boundaries.json --output /tmp/stone-router-boundaries.json
python data/case_2/voice_router_dataset/evaluate.py /tmp/stone-router-boundaries.json tests/router_boundaries.json
```

Unit-тесты используют mock API и проверяют контракт/подготовку запроса. Для оценки
классификации необходимы живые прогоны из команд выше.
